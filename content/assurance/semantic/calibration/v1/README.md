# Vajefy semantic judge calibration v1

This frozen set qualifies semantic judges before they are allowed to evaluate
release-bound A1 content.

## Why it exists

Public leaderboards are candidate-selection evidence, not Vajefy release
evidence. A model can look strong on generic benchmarks while still:

- missing Persian mistranslations;
- over-flagging correct A1 material;
- refusing to abstain when evidence is missing;
- violating the required JSON schema;
- changing decisions across repeated runs.

The calibration gate measures those behaviors directly.

## Frozen corpus

Version: `vajefy-semantic-v1`

Cases:

- English: 6
- Persian: 6
- Pedagogical: 7
- Adversarial: 9
- Total: 28

Categories:

- clean controls: 8
- seeded defects: 16
- abstention cases: 4

The gold labels come from deliberate controlled mutations and deliberately
withheld evidence. They are not generated by another model.

The model never receives the expected label. Calibration packets contain only
the target snapshot plus the role rubric/prompt.

## Pre-registered thresholds

Each role requires **three independent runs** of the exact same
provider/model/version/prompt/rubric.

Promotion requires all of the following:

- schema compliance: 100%
- seeded-defect recall: 100%
- clean false-positive rate: 0%
- clean uncertain rate: 0%
- abstention accuracy: 100%
- expected-label stability across repeated runs: 100%
- same candidate identity across all runs
- distinct run IDs and isolated context keys across all runs

These thresholds were committed before any candidate model was run against the
calibration set.

If the thresholds are changed after observing results, that must create a new
calibration version. Do not edit v1 thresholds post hoc.

## Commands

Validate the frozen set:

```sh
npm run assurance:semantic:calibration:check
```

Verify committed packets remain synchronized with the frozen cases and current
rubrics/prompts:

```sh
npm run assurance:semantic:calibration:packets:check
```

Run a candidate manually through the existing GitHub workflow:

1. open **Semantic judge (manual)**;
2. choose a role;
3. choose `calibration_v1`;
4. provide a unique run id;
5. explicitly acknowledge inference;
6. repeat three times for the same role.

Download the three role artifacts and score them:

```sh
npm run assurance:semantic:calibration:score -- \
  --role english \
  --run run-1.json \
  --run run-2.json \
  --run run-3.json \
  --require-promote
```

Record qualification only after the strict score passes:

```sh
npm run assurance:semantic:qualification:record -- \
  --role english \
  --run run-1.json \
  --run run-2.json \
  --run run-3.json
```

Then verify:

```sh
npm run assurance:semantic:qualification:check -- --role english
```

## Unit 1 lock

The manual semantic judge workflow now has two target sets:

- `calibration_v1`
- `unit1`

A `unit1` run is blocked unless the selected role has a current qualification
record for:

- the current calibration version;
- the current free-provider champion;
- the exact model version;
- the current prompt/rubric identity.

Changing the default model invalidates the old qualification automatically.

## Gold challenge policy

The calibration corpus itself is not infallible.

If a candidate consistently identifies a concrete defect in a clean control or
a mislabeled seeded case:

1. do not simply mark the model wrong;
2. inspect the case independently;
3. do not alter v1 after looking at candidate results;
4. if the gold label is genuinely wrong, create v2 with a documented rationale;
5. rerun all candidates on the new frozen version.

This prevents benchmark overfitting and post-hoc threshold manipulation.
